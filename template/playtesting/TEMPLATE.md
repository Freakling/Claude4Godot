# Playtest Report

> Copy this file to `playtesting/<version>/playtest_<#>.md` and fill it in after a play session.
> See GDD §13 (Playtesting Process) for how this feeds back into design revisions.
>
> **This is about how the game plays, not whether features exist.** Answer from the player's seat:
> what you decided, why, and how it felt. If a loop isn't in this build or you didn't reach it, write
> `skipped` and move on. Scores use the same statements every build so they can be compared over
> time; a score with no comment is still useful.

> §3/§5 (typically 5–8), each with one fixed scored statement. Changing a statement later is a GDD
> revision (§13.2). Keep the unnumbered sections below them (Pressure & Pacing, Reading the Game,
> Bugs, Free-Format Comments) as they are.
